## Gaps and manual checks

1. **Native confirmation handling:** clicking Unpublish stalled automation on the browser confirmation. The dialog API could not retrieve it. The user was asked to dismiss it, and remaining QC continued in a fresh tab. The API operation and resulting public 404 were verified separately. The confirmation's accept/cancel actions and native unsaved-navigation/sign-out confirmations still need a manual browser check. This does not establish a backend unpublish failure.
2. **No deletion control:** the current UI/API has no project/design deletion workflow. Removing QC data required narrowly scoped administrative cleanup. Project creation and historical-revision restoration also have no user-facing controls in this version.
3. **First preview wait:** a new preview hostname can display a blank iframe for several seconds while Caddy provisions its first certificate. It subsequently loads correctly; a visible loading indicator would make that wait clearer.
4. **Operational limits:** backup restoration, disaster recovery, disk exhaustion, concurrent load and other browser engines were not exercised. Historical files/publication snapshots have no automatic retention cleanup.
